# ADR-0006: Persistent development order journal

**Status:** Architecture approved by project owner on 25 November 2026, [Issue #70](https://github.com/Snahdul/HaMi-AI-Engineering-Agent/issues/70#issuecomment-7162605006); implementation and acceptance pending. Extends ADR-0004/0005 for new multi-step orders only. No V1 migration, no production dispatch or new external effects authorized by this decision.

## Decision and evidence

Use a domain bridge to the maintained Akka.Persistence SQL journal with SQLite. S01 test-only prototype at 111b66935c99b6035d4173324ab3a950c11275aa passed actual process kill and reentry on Windows and Linux ([CI 45613428906](https://github.com/Snahdul/HaMi-AI-Engineering-Agent/actions/runs/45613428906)); existing V1 claim/lease tests also passed. Reuse the host's canonical issue lease, protected account root and evidence store. Keep the host as authorization/lifecycle/effect owner. Only the journal owns mutable workflow state; the actor is a replayed view. A new job's immutable version-2 claim uses the same issue-N.json path and same issue-N.lock as V1. No second state file or lease. V1 can never resume a version-2 job; updated V1 lookup recognizes valid version-2 claims and rejects matching IDs while retaining V1 lookup of other jobs. Old binaries fail closed on unknown state schemas (including registry scan); downgrade is not a supported recovery procedure.

Prefer one private SQLite journal per job initially; bind stable persistence ID, approved archive and versioned events. No custom journal provider, cluster, DB server, snapshots or automatic migration. Keep current V1 publication recovery unchanged. Do not persist prompts or secrets. The host stores verified bytes and evidence before acceptance events, reserves operation identity and budget before dispatch, and reconciles uncertain effects instead of replaying them. RecoveryCompleted does not establish a valid job (empty journal also recovers). Validate expected journal identity, event history, artifact bytes and current authorization before further effects. Missing/ambiguous state fails closed. No automatic recreation, rollback, deletion or repair. Same-account/admin compromise, host loss and power loss remain outside the accepted process-crash boundary.

## S03 implementation increments

S03.1 creates a strict immutable claim and historical approval archive from the existing validated approval observation. Archive stores normalized plan, exact selected approval comment/identity/times and observed title/time, with all reviewed digests in the binding. It intentionally excludes unrelated Issue comments/raw discussion. Archive is not authenticated current authority. Claim first, then exclusively create and flush archive: an interrupted or missing archive blocks that issue; retain incomplete state. Use existing same-directory atomic claim replacement primitive (initial move without overwrite), private file creation and readback. The canonical claim and archive encode only host-produced records, with exact serialization checks and bounded size; no import or CLI path override. Fixed schema rejects duplicates/unknown fields and unrecognized versions. S03.1 adds deterministic offline tests; no SQLite production startup or external dispatch yet.

S03.2 must implement and prove protected journal bootstrap/reentry, ACL/UID/permissions and sidecars, link checks, real provider connection durability settings, exact artifact binding, missing/empty/wrong journal rejection and bounded native dependency/advisory/license review. S04 adds operational events, stable reservations and budgets; S05 verifiers; S06 actual orchestration; S07 full review. Do not enable a new production path before these gates. The existing test-only prototype remains separate from these production primitives until integration is verified.

## Alternatives

- Extend JSON checkpoints and own event replay: technically feasible, but repeats tested framework capabilities and increases custom journal code.
- Implement custom Akka journal provider: unnecessary with working standard SQLite provider; would require full replay/atomic write/sequence contract.
- Move all ownership into actors: insufficient cross-process and approval authority; retain host lease.
- Store both mutable JSON workflow checkpoint and journal: inconsistent after crash between writes; rejected.

### S03.2a – protected journal bootstrap and probe integration

The existing issue lease derives `issue-N.order.db` from the claim, not from a caller path. Only the lease which just created the immutable order claim and verified the archive may exclusively pre-create the empty private database file. Resume requires a nonempty SQLite header, correct private metadata and the bound archive; missing/empty journals never trigger creation. Orphan journal/sidecar paths block new V1/V2 claims. DELETE rollback mode is the initial restricted mode; preserve and validate any hot rollback sidecar, reject WAL/SHM rather than delete. The probe uses actual V2 claims, reopens under the existing ACL/UID checks in isolated temporary roots, and binds the first persisted event to the archive digest and PersistenceId. Test missing/empty database and conflicting V1 claims before normal reentry. The provider opens existing files in ReadWrite, pooling disabled, and uses documented LinqToDB DataOptions connection-open callbacks to require DELETE and set/check synchronous FULL on observed provider connections. The probe requires at least one observed actual provider connection. Full connection-path coverage (including provider cloning), live native sidecar metadata and failure/crash during a transaction, wrong journal/accepted artifact negatives, private artifact creation, resolved package/advisory/license review and actual HaMi11 production root remain open; no production SQLite dependency or dispatch yet. Existing V1 and current CI gates retained. Sources: https://www.nuget.org/packages/Akka.Persistence.Sql/1.5.73 ; https://linq2db.github.io/articles/FAQ.html ; https://www.sqlite.org/pragma.html .

### S03.2b correction: connection lifecycle

CI 45617802265 and diagnostic CI 45618584197 failed at probe readiness, both OS. The diagnostic confirmed CommandInitialized saw an unregistered Microsoft.Data.Sqlite.SqliteConnection. LinqToDB 6 deliberately delays connection opening until Execute*; the pinned v6.5.1 source (DataConnection.cs, DataConnection.Async.cs, Interceptors/CommandInterceptor.cs and ConnectionInterceptor.cs) shows command initialization is distinct from execution. Register a ConnectionInterceptor for synchronous/asynchronous open, and move the guard to all six sync/async ExecuteNonQuery/Scalar/Reader hooks, preserving the open + configured identity requirement and FULL/DELETE policy. No additional PRAGMA per SQL statement, no timeout extension, no unchecked fallback. A first guard failure signals the host's pending start/read/advance directly rather than waiting for the actor Ask timeout; further repeated error logging is suppressed. Actual provider-clone behavior still requires CI confirmation, and no assertion about unobserved native paths. Sources: https://github.com/linq2db/linq2db/wiki/Linq-To-DB-6 ; https://github.com/linq2db/linq2db/blob/v6.5.1/Source/LinqToDB/Data/DataConnection.cs ; https://github.com/linq2db/linq2db/blob/v6.5.1/Source/LinqToDB/Data/DataConnection.Async.cs ; https://linq2db.github.io/articles/general/interceptors.html .

### S03.2b correction: Windows native rollback ownership

CI 45621100834 on d39ce222: Linux complete success, actual guarded SQL/replay/private-artifact/rollback fixture PASS, SQLite native 3.53.4. Windows reached persisted S01 in about 2.2 s before failing the actual rollback file owner check (Administrators), not a connection guard or recovery timeout. Windows uses TOKEN_OWNER for objects created without an explicit descriptor; files inherit ACLs from the parent. The existing trust model already trusts local Administrators and SYSTEM, but requires the account SID as owner of host-created files. Keep that rule unchanged. Only the exact lease-derived `issue-N.order.db-journal` path receives a separate native rollback validator on Windows; permit account or built-in Administrators owner, preserve all existing canonical/non-null ACL, trusted allow-ACE, account-full-control and link checks. No global owner exception, no ACL/owner repair, no token modification, no WAL/SHM support, no Linux permission change. Synthetic Windows descriptor negatives reject the same administrator-owned file under ordinary validation, administrator-owned directories, SYSTEM owner under native policy, Everyone read access and absence of account full control. Actual sidecar and process-abort/reentry tests remain required. Reentry phase timing is now printed on successful child completion too; it is not an end-to-end S07 benchmark. No new dependencies or workflow. Microsoft references: https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_token_owner ; https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights . Package/license review and real designated-host acceptance remain open.

### S03.2c – dependency review and native patch

Actual actor replay after host start: accepted S01 Linux 933 ms/Windows 1045 ms; reserved unknown Linux 819 ms/Windows 1048 ms. These are not full S07 economic measurements.
